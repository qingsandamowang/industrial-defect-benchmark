# 学习说明：磁瓦缺陷检测与分割

## 先理解任务

一张磁瓦图像既有“是否存在缺陷”的图像级任务，也有“缺陷在哪些像素”的分割任务。前者由掩码是否含非零像素定义；后者使用原始像素掩码。正常图远多于缺陷图，且吹孔、裂纹等缺陷可能只有少量像素，因此单纯看准确率容易误导。

数据作者公开了图像和标注。先打开 `data/raw/mtd` 中每类一张 `.jpg` 及同名 `.png`，确认图像尺寸不一、掩码值只表示前景/背景。再看 `src/defectbench/data.py` 如何配对和分层划分。`manifest.json` 固定了具体图片名单，训练、验证、测试不可混用。

## 基线为什么弱

`baseline.py` 对整张灰度图做 Otsu 自动阈值，并清理小连通域。这种方法依靠全局亮暗差异，不能理解磁瓦纹理。正常图的光照起伏也会产生大片候选区域。测试集 Dice 0.080、AUROC 0.513 正是这类方法的真实限制，而不是应当藏掉的失败。

## U-Net 的关键点

`model.py` 的编码器逐层下采样提取上下文，解码器通过跳跃连接取回空间细节；最后一个 1×1 卷积输出每个像素的缺陷 logit。`training.py` 对正常与缺陷图做平衡采样，用加权二元交叉熵加 soft Dice 损失减轻前景稀少问题。填充到统一尺寸时保留长宽比；测试时把概率图恢复到原图尺寸后评估。

第 27 轮是验证 Dice 最高的权重；分割阈值 0.60、图像检测阈值约 0.203 都由验证集选择。图像级得分为预测概率最高 1% 像素的均值。测试集仅用来形成最后报告。指标定义在 `metrics.py`、汇总口径在 `reporting.py`：像素 Dice = 2TP/(2TP+FP+FN)，IoU = TP/(TP+FP+FN)。图像 AUROC 衡量缺陷图得分高于正常图得分的排序能力。

## 结果应怎样解释

30 轮配置的测试 Dice 0.575，相较 Otsu 0.080 有明显提升；图像 F1 0.594 表明仍有误报。Blowhole 类 Dice 0.262 是短板。打开 `results/mtd_v2/case_images`：每张图从左到右分别是原图、绿色真值、红色预测。小缺陷在 192×192 输入下容易丢失，光照纹理也会造成假阳性。报告中的分数适用于这次数据划分与本机配置，不能当作生产线性能。

## 建议自己动手的顺序

1. 手算一张 2×2 掩码的 TP、FP、FN、Dice 和 IoU，然后对照 `tests/test_metrics.py`。
2. 阅读 `preprocessing.py`，解释为什么掩码缩放用最近邻、图像缩放用线性插值。
3. 画出 U-Net 每层张量尺寸，说明跳跃连接如何帮助定位。
4. 先复现 Otsu 报告，再运行 128×128 和 192×192 两组模型，比较训练曲线与 Blowhole 类结果。
5. 从一张错误图分析漏检或误检原因，提出只在验证集上选择的改进，例如局部裁块或更高输入分辨率。
